## Native Row key/value rule — source evidence, not a hypothetical policy

1. `rust_engine/json.rs::source_id/source_pair` encode physical IDs as
   `source:` followed by the canonical JSON **two-string array**
   `[collection_name, encoded_logical_key]`. `source_pair` round-trips through
   `source_id`; a physical ID is NOT the collection row key.
2. `rust_engine/access.rs::Access::visible` authorizes the row with its encoded
   logical key, and additionally requires every selecting/index field to be
   readable. `Access::filter` then returns `(same_logical_key, redact(value))`.
   Redacting an unrelated field does **not** revoke authorized row-key disclosure.
3. `rust_engine/ranges.rs::scan_rows` uses no selecting fields for source-key
   scans, or the actual index fields for indexed scans; it decodes physical IDs
   with `source_pair`, filters candidates **before** its windows/limits/cursors,
   redacts values, and keeps those logical keys in the returned rows.
4. Actual generated SDK/HTTP fixture
   `service/authorization/sql_metadata_tests/application.mjs` and its bundled
   application prove ordinary `scan`, indexed scan on public `label`, and `range`
   return `[{key:"sql-policy",value:redacted_metadata}]`, while selecting/indexing
   hidden `sqlSources` returns **no row**. These are existing native service
   bodies, not a generic external raw-row endpoint. The native service test is
   `generated_system_access_reads_full_metadata_but_native_bodies_redact_it`.

Therefore the detached scan's former “any field redaction => Unsupported” branch
was unjustified and is removed. Object fields still come exclusively through
`RedactedRow::field`; hidden rows still disappear. No raw-field override exists.
The complete filtered/redacted batch must finish successfully before provider
execution, and the entire typed frame must finish before SQLite/COUNT/SUM/LIMIT.

### Concrete logical-key boundary and constructor

- Every host `OwnedRow.key: KeyId` is **encoded logical source-key text**, never
  `source:[...]`, `cell:`, `root:`, `collection:`, `index:`, or `$flower.*`.
  Those prefix-looking keys are fatal Forbidden even if the captured row is
  hidden or the requested get key is absent. Guest physical-looking get keys are
  rejected before issuing capture demand. This deliberately refuses a subset of
  ordinary Flower's otherwise legal string keys; it is not a native key grammar
  claim. Internal **collection names** remain forbidden. Legitimate logical
  strings like `__proto__` are not confused with internal collection names.
- `bind_owned_native_string_row(source_declaration_id, source_pair_id, row)`
  checks the actual captured native `Source{name,jsonKey}` declaration,
  canonical captured `[name,logical_key]` suffix, retained KeyId equality, and
  value offset in the same owned frame. A private `NativeLogicalKey` is issued
  only after this correlation. Canonical two-string array encoding is checked
  byte-for-byte with native serde escaping, in the original job's cumulative
  host budget; no `Value`, allocation, source callback or raw key resolver.
- `prepare_provider_input_from_native_catalog(source_declaration_id)` is the
  production-shaped input API. Native Source JSON shape is exact, camel-case
  `jsonKey`, default false as native serde specifies; unknown properties,
  caller `allowed`, or alternate `json_key` fail. Its source name binds the actual
  captured relation; missing/incomplete relation requires native capture, never
  an empty batch. Name-only convenience is **test-only**.
- `jsonKey:true` is explicitly Unsupported for this initial provider subset.
  The host does not pretend an encoded typed JSON string is already an SDK
  decoded key, nor infer key semantics from its text. Ordinary SDK
  `define.ts::encodeKey/decodeKey`, `sql.ts` generated provider adapter and native
  catalog `sql.rs::Source.json_key` define the required canonical JSON/decode
  behavior. Direct guest typed keys are Unsupported.
- Native capture origin/catalog membership, complete coverage, and mandatory
  constructor use are **controller obligations still HOLD**. Existing
  `OwnedRow/OwnedRelation` descriptor fields remain native-visible; these helper
  checks are not a cryptographic/native-root certificate and are not claimed to
  force every future controller to use them. No shared root/API import was
  changed by this child.

`rust_engine/sql/native.rs::source_cell` derives declared sourceKey from the
encoded logical key and sourceField from the **already-redacted candidate**
selected by that ordinal, not the provider cell. New sealed-frame COUNT/SUM tests
apply that same rule using complete actual native-filtered batches; they never
substitute an unreadable raw field. General native column-kind/nullability,
sourceKey/sourceField insertion into the terminal controller still needs parent
integration; a tagged provider cell alone is not that proof.

### Actual private-field policy distinction

The frozen main/backend collection manifests have **no field-read rules on
`sessions` or `reports`** (their manifests are identical). Backend guard fields
like `sqlSources` are excluded by curated DTOs/closed HTTP aliases and used by
higher-level SQL custody checks; they must not be described as already protected
by a processes-only collection field rule at these SHAs. Real account fields
(`userHandle/github/invite`), org `settings`, scope `instructions`, and other
listed fields do have actual field ACLs. The synthetic native metadata fixture
proves the native field-ACL mechanism, not automatic installation of new guard
field rules on the real Ultimator deployment. This audit does not invent a
public raw-row endpoint: only stored HTTP aliases are externally callable.

## Actual operator and temporal compatibility

| Actual feature | Owned native support / required constraint |
|---|---|
| `const`, non-temporal `all/any/not` | Supported, exact whole-tree validation; short-circuit truth agrees with native. |
| `eq`, `exists`, `in` (including principal subject in invited/reach/overseers/member arrays) | Supported. Array membership is not a public classifier. |
| `startsWith` | Supported for the existing fixed captured string operands. |
| `principal.subject/tenant/claims`, row nested paths, whole string key | Supported bounded native operands; verified principal derives only from native binding. |
| `key.at(0/1/...)` / typed JSON key parts | **Unsupported**; actual policies need this, even if a privileged process branch would otherwise win. |
| `readable(target,string_key)` | Actual target read ACL plus explicit captured row/absence required; unknown absence issues NeedCapture. Target read rules cannot themselves use readable. |
| `readable` with array/object key operand | **Unsupported**, not stringified heuristically. |
| Scalar `now` comparisons | Policy engine's existing exact exclusive validity boundary, numeric-domain limits and original native clock apply; not used by these frozen collection read trees. |
| Temporal `all/any/not`, including readable target time | Existing **UncertifiedTemporal** refusal retained. No rule/expiry exception was added. |
| Host `query/range`, indexed/options scan | **Unsupported**; a hidden selecting field is tested directly through actual PolicyEngine/native reference, not a invented detached range implementation. |
| Host `changesAt` | **Forbidden**. Actual backend `certifiedSqlContext` needs it; this is a real terminal compatibility blocker. |

All frozen collection read/field-read trees use only
`all,any,const,eq,exists,in,not,readable,startsWith` and **zero `now` references**.
Thus the stricter temporal-compound refusal does **not** itself explain failure
of this frozen collection ACL matrix. Expiry lives in real method/provider code,
not in these collection read ASTs. In particular:

- `app/kernel/schema/sessions.ts` permits overseers through `overseers[]`;
  `app/kernel/access.ts` checks current oversight expiry and membership.
  The differential test deliberately demonstrates that the collection ACL still
  returns true for a listed overseer with an already-expired `oversight` timestamp.
  That is **not** permission to publish SQL after expiry.
- `app/access/oversight.ts` maintains arrays through timers, but SQL must respect
  `oversight[subject]` even if the timer has not committed yet.
- `app/access/integrations.ts`, `app/access/authority.ts`, `app/access/audiences.ts`
  refresh integration ownership/audience, live grants, limits/expiry, membership,
  roles, actors and recipient rights. Native collection ACLs alone are weaker.
- Backend `app/sql/context.ts::certifiedSqlContext` fixes `now` to native `clock`,
  declares principal JWT expiry, row/lease/limit/oversight expiry via `changesAt`,
  and performs paginated range/options-scan support reads. The detached host
  currently refuses these operations. No expiry is silently waived.

### Smallest exact remaining semantic extensions for the parent

1. **Typed-key subset:** capture a native catalog-correlated canonical decoded
   typed key in owned frame slabs, bind it to the encoded KeyId/source pair,
   initially support the actual tuples of strings and JS-safe integer parts,
   and make policy key-part resolution use that owned value. Decode/encode must
   match SDK canonical JSON and current native key-part semantics, with no
   allocating Value parser; all other typed cases explicitly refuse. Merely
   adding caller `jsonKey:true` or changing key-part refs into whole-key equality
   is not sufficient. This is needed by actual `members/scopes/labels/usage`.
2. **Native temporal declarations:** a narrowly metered `changesAt` certificate
   collector would need to preserve the original clock/job, enforce valid safe
   future integer boundaries, intersect the exclusive earliest boundary, and
   bind those declarations to captured code/support dependencies and final fresh
   publication. It must not turn guest-selected later expiry into authority.
3. If an actual future collection read rule adds a temporal compound, the small
   exact policy extension is a bounded **whole-tree temporal leaf certificate**
   pass: resolve/certify every clock-bearing leaf (including unread/eager-invalid
   branches and actual readable target leaves) under existing scalar proofs,
   then intersect safe exclusive boundaries through all/any/not while preserving
   native truth. Removing the current compound refusal without proving skipped
   leaves, or using now/ctx.clock as a stability assertion, is not acceptable.

No parent-owned policy/frame/crypto/service/evaluator/SDK file was edited here.
