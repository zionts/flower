Experimental terminal foundation: unavailable

HOLD, not a released or serving SQL interface. Cargo's default features remain empty. The native SQL foundation is compiled only with --features sql; the explicit Nix flower-sql package selects that feature while flower and the default package/app keep it off. Compiling this artifact does not open the serving gate.

Legacy ctx.sql is permanently on HOLD. Complete retention of its original serving snapshot has not been hard-bounded: Records::sql_snapshot_reservation_bytes() returns no reservation for any root. The feature-enabled legacy path refuses it with SQL_SNAPSHOT_UNBOUNDED, and the default build refuses native SQL with SQL_UNAVAILABLE. There is no public/test bypass or legacy execution fallback for a terminal declaration.

sqlMethod declares the replacement detached terminal contract. Its native capture/seal/execute/fresh-finish lifecycle is not implemented or enabled yet; the service currently refuses terminal requests with SQL_TERMINAL_UNAVAILABLE. SDK/SQLite allocator tests, manifest metadata, and an opt-in package are not positive native/provider-policy conformance evidence. Read SQL.md and src/consensus/records_sql_snapshot.md for the hard gates. Collections are never automatically SQL-readable.

Readless plan and three-argument finalizer

APIContract
sqlMethod(name, spec): QueryMethodDedicated terminal declaration for a fixed catalog and operation. Forces cache:false and watch:false. Schema-validated args/access remain application policy. Generates a dedicated finalizer named name.$sql.finalize. Without a custom finalizer, the public result is returned, never query provenance. Native execution is still unavailable.
SqlOperation"query" | "explain" | "catalog" | "cancel". Selected by the deployed declaration, not an arbitrary callback named by client input.
SqlMethodSpec<A,O,V>catalog, operation, optional args/access, plan(invoker,args), finalize(ctx,execution,metadata), and signingKeys. No cache/watch override or ordinary-query/ctx.sql fallback. A schema argument infers A; V is the finalizer's return type.
SqlTerminalRequest{input,purpose}; input is SqlQueryInput, {queryId}, or null. Both properties are required. Purpose remains untrusted until the deployed catalog authority validates it.
SqlFinishBindingTrusted finish binding: invoker, effective principal, clock, history, codeVersion, catalogVersion, authorityContext, sourceRevision, and partition:{name,epoch}|null. Native fresh-finish validation must supply it; client args/result fields cannot.
SqlFinishMetadataSqlFinishBinding plus request:SqlTerminalRequest. The third finalizer argument, separate from execution; sourceRevision/history bind disclosure evidence to the actual source capture.
SqlFinishContextOnly principal(), clock(), history(), codeVersion(), and readonly binding. No source getter, SQL, writes, definer elevation, ambient now(), or secret handle. The SDK adapter freezes this readless context from the trusted finish binding.
SqlPublicResult<O>query → SqlResult; explain → SqlExplain; catalog → SqlCatalogInfo; cancel → boolean. Default public method result.
SqlOperationResult<O>query → SqlExecution ({result,provenance}); other operations → SqlPublicResult<O>. This is the finalizer's second argument, not always a query wrapper.
SqlFinishInput<O>Trusted callback transport {request,result,provenance,binding}. The SDK adapts it to exactly finalize(ctx,execution,metadata), with the query wrapper only for query. Not client input or a public response.
SqlTerminalMetadata{catalog,operation,finalizer,signingKeys}. Frozen metadata emitted on both the query definition and HTTP alias. The finalizer reference must resolve to a dedicated sqlFinalizer definition.

plan(invoker,args) has no database context: only the actual verified invoker (or null) and validated method args. The default plan returns {input:args ?? null,purpose:null}. It does not confer authority. finalize(ctx,execution,metadata) has exactly three arguments; no authorization/source reads may be deferred into it. A human query finalizer should return execution.result, not internal provenance.

signingKeys is an explicit list of at most eight declared managed keys, each with sign usage; a nonempty list requires a custom finalizer. The SDK adds those declarations to the application key manifest. The native finish boundary must restrict managed-key use to these keys and signing operations only; declarations do not grant secret bytes or enable that lifecycle today. Any agent proof still needs independent atomic current-audience/exposure admission before delivery or logging.

The required replacement lifecycle is detached: quota-first owned bounded capture, no original Records root/read pin held across guest callbacks or SQLite, an immutable seal containing only authorized typed rows, then fresh bounded authority/source/expiry/code/history checks before the readless finalizer. Storage, frame, callback, cancellation and signing gates must pass together; none is waived by --features sql.

Authority ends before providers

APIContract
SqlReadContextCollection point reads and bounded declared-index reads, principal/history/codeVersion and certified clock/changesAt. The type retains now(), but polled/uncertified temporal authority must fail closed. No writes, definer elevation, derived reads, SQL recursion, managed keys, filesystem/network or entropy. This is not the readless plan/finalizer context.
SqlAuthorityContextDedicated pure deployed validation callback. Application auth-row read rights do not flow into providers; users cannot provide an effective principal.
SqlProviderContextDedicated rights-preserving projection callback, not a derived value. Effective invoker, data/policy dependencies and cumulative budgets must remain bound to the capture.
SqlAuthorityRequest{catalog,invoker,purpose}; raw purpose is untrusted. Verify current human authority or a live database-local captured session grant/generation/lease and destination audience.
SqlAuthorityDecision{principal,context,tables} or null from authorize. tables is an explicit logical allowlist, also applied to discovery. Only validated context reaches provider purpose.
SqlProviderInput{source:{name},rows:[{key,value}],purpose}; bounded candidates are already collection-ACL filtered/redacted. SDK decodes JSON keys; native sourceKey columns intentionally retain encoded text.
SqlProjectedRow{sourceRow,cells}; sourceRow is a validated batch-local ordinal. Native mapped columns override placeholders from that exact redacted candidate.
SqlProviderBatch{rows,provenance?}. Provenance is bounded trusted internal evidence; never expose it as human cells/catalogs/errors or log it on failure.

Temporal policy helpers must use clock() and declare every known future expiry with changesAt(). Delivery must reauthorize on fresh serving state and validate source/policy dependencies and expiry rather than silently rerun or emit a partial aggregate. This is a launch requirement, not a claim that terminal serving currently performs it.

The legacy method signatures remain documented only as source contracts: query(catalog,input,purpose?) → SqlExecution; catalog(catalog,purpose?) → SqlCatalogInfo; explain(catalog,input,purpose?) → SqlExplain; cancel(catalog,queryId,purpose?) → boolean. No terminal declaration calls those methods. Terminal cancellation must reauthorize the original/effective principal, purpose, partition and query ID, with permits retained until actual termination.

Trusted one-shot HTTP envelopes carry history:{database,incarnation}|null beside revision/value, not inside application result data. Terminal completion must bind the exact sourceRevision/history rather than accept client or result-field substitutes. The Node testDatabase refuses native SQL. Real-server tests must currently confirm HOLD; no positive terminal/provider conformance or Nix evaluation/build is claimed here.
